# Verbatim STT Gold Transcript 작성 규범

규칙 식별자: `gold-v1-rc1` · 상태: **검토용 규범안, 실제 음성 파일럿 검증 전**

이 문서는 기존 `gold-v1` 초안을 재작성한 첫 번째 검토 후보(rc, release candidate)다.
이번 문서 변경은 모델·프롬프트·채점 코드의 변경이나 모델 품질 개선의 증거가 아니다.
이미 이전 초안으로 만든 자료가 있다면 새 규칙으로 검수하기 전까지 기존 버전을 유지한다.

## 1. 무엇을 정답으로 삼는가

Gold Transcript는 **특정 음성 파일에서 들리는 발화를, 명시된 규칙으로 기록하고
사람이 검수한 기준 자료**다. 같은 시험지를 채점할 때 사용하는 정답지에 해당한다.
좋은 Gold는 문장이 매끄러운 자료가 아니라, 다른 작성자가 같은 규칙과 음성으로
다시 작성했을 때 같은 판단에 도달할 수 있는 자료다.

이 프로젝트의 목표는 영어 OPIc 연습 발화의 **철자 기반 verbatim 전사**다.
철자 기반이라는 말은 알아들을 수 있는 단어를 일반적인 철자로 적는다는 뜻이다.
Verbatim이라는 말은 필러, 반복, 중단, 자기 수정, 실제 문법 오류까지 보존한다는 뜻이다.
모든 소리를 발음기호로 기록하는 음성학 전사나 OPIc 답변의 문법 교정과는 목적이 다르다.

정답은 다음 우선순위로 결정한다.

1. **음성 증거:** 실제로 발성한 단어·조각·사건과 순서를 보존한다.
2. **표기 규칙:** 같은 현상을 같은 철자와 단위로 적는다.
3. **불확실성:** 증거가 부족하면 그 상태를 기록한다. 문장을 완성하려고 추측하지 않는다.
4. **채점 호환성:** 채점기가 처리하지 못하는 정보도 Gold에는 남기고 평가 범위를 제한한다.

채점기가 단어 조각을 처리하지 못한다는 이유로 Gold에서 말더듬을 삭제해서는 안 된다.
또한 사람의 합의는 절차적 신뢰도를 높이지만 절대적인 진실을 보장하지 않는다.
확정 후에도 원음에 근거한 정정과 이력 관리가 가능해야 한다.

### 적용 범위

- 기본 대상은 한 명의 목표 화자가 말한 영어 답변이다. 작은 목소리, 비원어민 억양,
  느린 말, 문법 오류만으로 자료를 제외하지 않는다.
- 한국어 혼용, 다른 화자와의 겹침, 불명확한 발화도 Gold에는 기록한다.
  현재 영어 채점기로 평가 가능한지는 별도로 결정한다.
- 전사문만으로 발음 정확도·강세·음질·임상적인 말더듬 여부를 판정하지 않는다.
- 질문, 모범 답안, 화자의 의도, 평가 LLM의 수정문은 정답을 대신할 수 없다.

## 2. Gold 원본과 채점용 텍스트의 관계

사진 원본을 보관한 채 인쇄용 사본을 만드는 것처럼, 전체 발화를 기록한 Gold에서
현재 채점기가 읽을 수 있는 단어열을 별도로 만든다. 이 변환을 **채점용 추출**이라 한다.
아래의 manifest는 평가할 파일과 정답을 나열한 목록 파일이고,
WER(Word Error Rate)는 정답 단어에 비해 대체·삭제·추가된 단어가 얼마나 되는지 나타낸다.

| 자료 | 담는 내용 | 현재 코드 지원 |
|---|---|---|
| 음성 파일 | 모든 판단의 근거가 되는 동일한 입력 파일 | 실행 CLI가 읽음 |
| `samples/<id>.gold.json` | 기준 전사, 단어 조각·사건·시간, 검수 상태와 근거 | 작성 규범안만 있음. 자동 검사·추출·채점 미구현 |
| manifest의 `referenceTranscript` | 현재 WER에 넣을 확정된 완전한 단어열 | 스키마와 채점기 구현됨 |
| 모델 실행 결과 | 모델이 반환한 수정하지 않은 전사문 | run JSON으로 저장·채점 가능 |

Gold 파일의 `verbatimTranscript`에는 완전한 단어를 그대로 쓰고, 일반 단어로 표현할 수
없는 사건은 `[종류:ID]`로 표시한다. 해당 ID의 실제 내용과 시간은 `events`에 둔다.
예를 들어 `[fragment:f1]`과 `heard: "w- w-"`가 함께 있어야 두 조각이 보존된 것이다.
태그만 남기고 실제 들린 조각을 버려서는 안 된다. 태그는 발화가 아닌 작성자 표식이다.

**현재 manifest에 `verbatimTranscript`, `events`, 검수 상태를 추가하지 않는다.**
현 스키마는 이런 필드를 지원하지 않는다. Gold JSON은 별도 비공개 파일이며,
이 문서의 예시는 향후 프로그램이 보장하는 파일 계약이 아니다.

### 채점용 추출 규칙

1. 완전한 단어·필러·반복·버린 구절의 완전한 단어를 모두 원래 순서로 남긴다.
2. 대괄호 사건과 시간 숫자·설명은 `referenceTranscript`에 복사하지 않는다.
3. 단어 조각을 완성 단어로 복원하거나 앞뒤 단어와 임의로 합치지 않는다.
4. 불명확한 구간을 지우고 남은 문장만 정답이라고 채점하지 않는다.
5. 추출한 결과를 다른 검수자가 Gold와 대조한다. 현재 자동 추출기는 없다.

## 3. 모든 작성자가 지켜야 할 공통 규칙

이 문서의 **반드시**는 확정 Gold의 필수 조건, **금지**는 허용하지 않는 처리다.
판정이 어려운 사례는 임시로 기록할 수 있지만 필수 조건을 충족하기 전에는 확정하지 않는다.

- 모델 출력·자동 자막을 보기 전에 사람이 먼저 듣고 작성한다. 비교 대상 STT의
  전사문을 수정해서 Gold를 만들면 그 모델의 누락이나 해석을 그대로 물려받을 수 있다.
- 첫 청취는 정상 속도로 전체 맥락을 듣는다. 반복·감속 청취는 가능하지만 마지막에
  정상 속도로 다시 확인한다. 감속으로 생긴 인공적인 경계를 원래 발화로 세지 않는다.
- 들린 단어를 추가·삭제·재배열하지 않는다. 화자의 수정 발언도 앞선 발언과 함께 남긴다.
- 문맥은 소리가 허용하는 후보를 판단하는 보조 증거로 사용할 수 있다. 문맥만으로
  들리지 않는 관사·시제·복수형·예상 답변을 채우는 것은 금지한다.
- 질문·고유명사 목록 등 보조 자료를 썼다면 종류와 사용 이유를 검수 기록에 남긴다.
  모델에 제공하는 입력과 사람이 참고한 자료를 구별해서 실험 기록에 명시한다.
- 조용하거나 부자연스럽다는 이유로 누락하지 않는다. 화자의 악센트를 과장한 철자를
  만들지 않는다. 알아들을 수 없는 음성은 억지로 영어 단어에 맞추지 않는다.
- 문장부호와 대소문자는 읽기 위한 보조다. 쉼표·마침표·물음표는 최소로 사용하고
  중단 경계는 `—`로 적는다. `...`로 생략이나 pause 길이를 표현하지 않는다.

## 4. 필러·반복·중단·오류의 결정 규칙

### 4.1 필러와 감탄·응답 소리

필러는 `um`, `uh`처럼 말을 고르는 동안 실제로 발성한 소리다. 무음과 구별하고,
음절 수나 철자를 늘려 지속 시간을 표현하지 않는다. 길게 한 번 발성한 `uh`는
`uh` 한 개, 별도로 두 번 시작한 발성은 `uh uh`로 적는다. 단순한 음량 변화만으로 나누지 않는다.

| 들리는 형식 | 기준 표기 | 구별 기준 |
|---|---|---|
| 모음 뒤 입술을 닫는 비음이 붙은 망설임 | `um` | 모음과 끝의 비음이 하나의 발성인지 확인한다. 뒤 단어의 `m`을 가져오지 않는다. |
| 중성 모음 위주의 망설임 | `uh` | 끝 비음이 없는 망설임이다. 모든 비음 없는 소리를 `uh`로 합치지 않는다. |
| r 계열 소리가 분명한 망설임 | `er` | r 소리가 확인될 때만 구별한다. 철자 `er`로도 쓸 수 있다는 이유로 바꾸지 않는다. |
| 열린 모음의 발성 | `ah` | 발화 기능이 망설임인지 감탄인지와 별개로 소리의 표기를 보존한다. |
| 입을 닫은 채 코로 울리며 낸 발성 | `hmm` | 모음 뒤 비음이 붙는 `um`, 단순한 숨소리·무음과 구별한다. |
| 분명한 긍정·부정 응답 | `uh-huh`, `uh-uh`, `mm-hmm` 등 | 실제 형식을 적고 `yes`나 `no`로 번역하지 않는다. |

`hmm`은 이 규칙에서 단독 humming형 발성의 통일 철자다. `hm`, `mmm`처럼 길이에 따라
철자를 바꾸지 않는다. 반면 응답 소리 `mm-hmm`까지 `hmm`으로 합치지 않는다.
확정할 수 없는 형식은 `uncertain` 사건으로 보류하고, 후보와 구별이 어려운 이유를 남긴다.
새로운 소리는 다섯 가지 필러 목록에 억지로 넣지 않고 표기 사전에 판정을 추가한다.

`well`, `like`, `you know`, `I mean`도 들리면 그대로 적는다. 필러처럼 쓰였다는 이유로
삭제하거나 한 단어로 합치지 않는다. 현재 자동 필러 지표는 오직
`um/uh/er/ah/hmm` 철자를 세며 담화 기능을 이해하지 못한다. `ah`가 감탄이어도 세고,
`mm-hmm`을 잘라 일부만 셀 수 있으므로 그 수치를 전체 필러 정확도로 부르지 않는다.

### 4.2 완전한 단어·구절 반복

반복한 단어는 매번 적는다. `I I I went`를 `I went`나 `I (x3) went`로 바꾸지 않는다.
구절 반복도 `I went I went home`으로 모두 남긴다. 강조·망설임·수사적 반복의 이유를
판단하지 못해도 단어 자체의 전사는 확정할 수 있다.

`I uh I`는 그 순서 그대로 적는다. 필러를 빼서 `I I`를 만들지 않는다.
`I had had lunch`처럼 문법적으로 자연스러운 반복도 같은 방식으로 쓴다.
현재 인접 반복 지표는 반복의 원인을 구별하지 못하며, `I uh I`나 구절 반복을
인접한 같은 단어의 반복으로 측정하지 못한다.

### 4.3 False start와 자기 수정

False start는 말을 시작했다가 일부를 버리고 다시 이어가는 현상이다.
버린 말도 실제 발화이므로 다음처럼 보존한다.

| 들린 발화 | 기준 전사 | 금지하는 정리 |
|---|---|---|
| `I went to`에서 멈추고 `I stayed home` | `I went to— I stayed home.` | `I stayed home.` |
| `on Monday` 뒤 `no on Tuesday` | `On Monday— no, on Tuesday.` | `On Tuesday.` |
| `I was` 뒤 `I am happy` | `I was— I am happy.` | `I am happy.` |

`no`, `sorry`, `I mean`을 실제로 말했을 때만 적는다. 중단했다고 자동으로 넣지 않는다.
미완성 문장이라고 마지막 단어를 조각으로 처리하지 않는다. `I wanted to`에서 녹음이
끝났다면 완전하게 발성한 `to`까지 보존하고 끝 잘림은 별도로 기록한다.
중단인지 단순한 쉼인지 애매해도 단어가 확실하면 단어 Gold는 유지할 수 있다.
사건 유형만 미확정으로 기록한다. 모든 사건 분류의 불일치가 곧 단어 불일치는 아니다.

### 4.4 단어 조각, 부분 반복, 늘임, 단어 내부 중단

완전한 단어를 반복한 것과 단어 일부만 발성한 것을 구별한다.
짧게 발음했다고 조각인 것은 아니다. 완전한 `I` 두 개는 `I I`이고,
자음만 시작한 `w-`는 단어 `went`도 알파벳 이름 `W`도 아니다.

| 현상 | Gold에 보존할 내용 | 채점용 단어열과 주의점 |
|---|---|---|
| `w- w- went` | `fragment` 사건에 `w- w-`, 부분 반복이라는 설명, 뒤의 `went` | 추출하면 `went`. 그러나 현재 주 비교 WER에서는 해당 샘플을 분리한다. |
| `becau-`에서 버리고 `well` | 확인된 조각 `becau-`와 완전한 `well` | `because`를 만들어 넣지 않는다. |
| `s`를 늘인 뒤 `so`를 완성 | `so`와 `prolongation` 사건 | `s s so`로 바꾸지 않는다. 단어는 한 번이다. |
| 한 단어 안에서 멈췄다 이어 말함 | `word-break` 사건, 들린 부분과 전체 단어 판단 근거 | 한 단어임이 합의될 때만 완전한 단어 한 개로 추출한다. |
| 소리 없이 막힌 듯한 순간 | 관찰 가능한 무발화 구간과 불확실성 | 소리만으로 임상적 `block`이나 의도한 단어를 확정하지 않는다. |

조각의 `heard`는 들린 부분까지만 일반 철자로 적고 끝에 `-`를 붙인다.
이 철자는 음성학적 정밀 측정이 아니다. 가능한 철자가 여러 개면 후보를 검수 기록에
남기고 조각 표기 확정을 보류한다. 조각이 뒤 단어의 시작과 같아도 빠진 부분을 보충하지 않는다.
연속 조각을 하나의 사건에 묶을 때도 `w- w-`처럼 각각의 횟수와 순서를 보존한다.
조각 사이에 완전한 단어나 필러가 끼면 별도 사건으로 나누어 그 순서를 유지한다.

**현재 비교의 함정:** 정답을 `went`, 모델 출력을 `w-went`로 놓으면 현 채점기는
`w`를 삽입 오류로 센다. 충실한 조각 보존이 오히려 감점될 수 있다.
따라서 조각·단어 내부 중단이 있는 샘플은 Gold를 유지하되 별도의 수동 검토 묶음으로
관리한다. 원문에서 조각을 지운 모델을 더 좋은 verbatim 모델이라고 결론 내리지 않는다.
향후 양쪽에 같은 추출 규칙을 적용하는 채점기가 검증되기 전까지 주 WER에 합치지 않는다.

### 4.5 문법 오류·잘못 선택한 단어·비원어민 발음

`She go yesterday`, `two informations`, `I goed there`가 분명히 들리면 그대로 적는다.
시제, 단복수, 관사, 전치사를 고치지 않는다. `goed`처럼 비표준 활용형도 임의로
`went`로 바꾸지 않는다. 새 비표준 형태는 표기 사전에 소리 근거와 함께 기록한다.

`hospital`을 분명히 말했으면 문맥상 호텔을 뜻한 것 같아도 `hospital`이다.
화자가 나중에 `hotel`이라고 고쳤다면 두 단어를 순서대로 남긴다.
화자의 사후 설명은 의도를 알려줄 수 있지만 기존 녹음에서 들린 말을 바꾸는 근거는 아니다.

악센트가 있어도 단어 정체성이 명확하면 통상 철자를 쓴다. `park`를 한국식 억양으로
발음했다는 이유로 임의의 소리 철자를 만들지 않는다. 다만 실제 형태를 바꾸는
명확한 `-s`, `-ed` 등의 유무를 문법적 기대만으로 복원하지 않는다.
`rice/light`, `walk/walked` 등 경쟁 후보가 음성 증거로 해결되지 않으면 `uncertain`으로 남긴다.
알아들을 수 없는 비단어는 익숙한 단어로 고치지 않고 `unintelligible`로 처리한다.

문법·어휘 오류의 교육적 판정은 별도 LLM 평가 영역이다. Gold에는 발화를 기록하며,
오류 원인이나 올바른 대체 표현을 정답 단어열에 섞지 않는다.

## 5. 철자·단어 경계를 고정하는 규칙

WER는 단어의 개수와 순서를 비교한다. `twenty one`과 `21`처럼 의미가 같아도
현재 채점기에서는 다른 단어열이다. 따라서 아래 표기 결정을 모든 작성자에게 적용한다.

| 항목 | 이 프로젝트의 규칙 | 예시 |
|---|---|---|
| 표준 축약형 | 실제 축약 발화는 축약형, 분리 발화는 분리형을 쓴다. | `I'm` / `I am`, `can't` / `cannot`, `don't` / `do not` |
| 구어 축약 | 분명하게 확인된 `gonna`, `wanna`, `gotta`, `kinda`는 유지한다. 새 형식은 표기 사전에 추가한다. | `I'm gonna go`를 `I am going to go`로 바꾸지 않는다. |
| 경계가 애매한 축약 | 정상 속도·국소 재청취 후에도 후보가 남으면 `uncertain`으로 보류한다. | `wanna`와 `want to`를 모델 출력에 맞춰 결정하지 않는다. |
| 숫자·시간·금액 | 말한 단어 형태로 쓴다. 수치 표기로 변환하지 않는다. | `twenty one`, `two thirty`, `five dollars`, `oh`와 `zero` 구별 |
| 알파벳 이름 | 하나씩 읽었으면 글자를 공백으로 나눈다. | `U S A`, `A I`; 단어로 읽은 `NASA`는 한 단어 |
| 동음이의어 | 음성과 발화 문맥으로 확인되는 일반 철자. 해결되지 않으면 후보를 보류한다. | `their/there`, `two/too`를 무조건 서로 같은 것으로 만들지 않는다. |
| 일반 철자 변형 | 미국식 철자를 기본으로, 변형·합성어는 공통 표기 사전에서 고정한다. | `color`, `favorite`; 합성어의 붙임·띄어쓰기를 임의로 바꾸지 않는다. |
| 고유명사 | 음성으로 단어를 식별한 뒤 검증 가능한 통용 철자를 쓴다. 근거를 기록한다. | 장소 `Seoul`; 비공개 실명은 평가 자료 선정 단계에서 제외 |
| 부호 | 축약형의 apostrophe를 유지한다. 다른 부호는 최소화한다. | `we're`를 `were`로 만들지 않는다. |

공통 표기 사전은 비공개 `samples/gold-lexicon.json` 등 하나의 자료로 관리한다.
항목에는 기준 표기, 적용 조건, 구별해야 할 발화, 결정 이유, 적용 규칙 버전을 기록한다.
현재 이 사전을 자동 적용하는 기능은 없다. 모델 답안에 맞춰 사후에 동의어·숫자
치환표를 추가해서 점수를 높여서는 안 된다.

현재 `I'm`과 `I am`, `21`과 `twenty one`, `USA`와 `U S A`는 동등 처리되지 않는다.
이 차이는 음성 인식 오류 외에 **출력 표기 방식의 차이**도 점수에 섞일 수 있음을 뜻한다.
원시 점수와 수동 오류 분류를 함께 읽고, 별도 정규화 점수가 필요하면 양쪽에 동일하게
적용하는 규칙을 먼저 버전 고정·검증한다. 모델 원문은 보존한다.

## 6. 불확실성·혼용 언어·여러 화자

| 상태 | 기록과 판정 | 현재 평가 처리 |
|---|---|---|
| `uncertain` | 소리는 들리지만 둘 이상의 단어·필러·조각 후보가 남음. 후보는 검수 메모에 기록 | 단어열이 달라지는 불확실성이 남으면 주 WER에서 보류 |
| `unintelligible` | 발화는 있으나 안정적으로 단어를 복원할 수 없음 | 구간과 이유를 남기고 주 WER에서 보류 |
| `non-speech` | 호흡·기침·웃음·잡음 등 언어적 단어가 없는 사건 | 단어로 쓰지 않음. 알아듣는 발화와 공존할 수 있음 |
| `foreign-speech` | 목표 화자의 한국어 등 영어 외 발화 | 해당 언어를 아는 작성자가 원어로 기록, 번역 금지. 현 영어 WER에서 분리 |
| `other-speaker` / `overlap` | 목표 화자 외 말소리 또는 동시에 말한 구간 | 화자와 구간을 구별하여 보존. 현 단일 화자 평가에서 분리 |

`I [unintelligible:u1] home`에서 모르는 부분을 삭제하여 `I home`만 정답으로 삼지 않는다.
알 수 없는 단어 수를 임의로 하나라고 정하지 않는다. 시간 범위를 한 사건으로 기록한다.
완전히 알아들을 수 없는 말도 무음은 아니다. `empty-or-rejected`로 재분류하지 않는다.

한국어 `어`, `음`을 자동으로 영어 `uh`, `um`으로 번역하지 않는다. 소리만으로 언어가
정해지지 않는 망설임은 음형 규칙으로 기록하고 언어 판정은 보류할 수 있다.
분명한 한국어 단어나 구절은 원어로 보존한다. 현 단어 분리기는 한글을 채점에서
떨어뜨리므로 혼용 문장을 넣고 전체 전사 정확도라고 보고해서는 안 된다.

웃으면서 말해도 단어가 들리면 단어와 웃음 사건을 함께 남긴다. 들리지 않는 부분은
웃음에 가려졌다는 이유와 함께 보류한다. 녹음 시작·끝이 잘렸다면 확인된 부분만
기록하고 잘린 단어를 완성하지 않는다.

보류 자료도 어렵다는 이유로 폐기하지 않는다. 전체 자료 수, 보류 수, 이유별 수를
공개 가능한 집계로 함께 보고한다. 명확한 음성만 남긴 WER는 어려운 실제 녹음
전체에 대한 성능을 대표하지 않는다. 보류 결정은 후보 모델 결과를 보기 전에 한다.

## 7. Pause와 시간 주석

### 7.1 무엇을 멈춤으로 기록하는가

여기서 pause는 **목표 화자의 단어·단어 조각·필러가 이어지지 않는 시간 구간**이다.
방 전체가 완전히 조용하다는 뜻은 아니다. 배경 소음이나 들숨이 포함될 수 있으며
그 사건은 따로 표시한다. `uh`를 내는 시간은 pause가 아닌 필러다.
일반적인 자음의 닫힘·소리 사이의 미세한 간격을 모두 망설임으로 세지 않는다.

검토 후보 `gold-v1-rc1`에서는 수동 주석 범위를 맞추기 위해 다음 기준을 사용한다.

- 문장 내부의 독립적인 무발화 간격은 **0.20초 이상**을 pause 후보로 기록한다.
- 이 값은 작성자가 선택할 구간을 맞추기 위한 프로젝트의 잠정 운영 기준이다.
  OPIc 감점 기준, 정상·비정상 경계, 검증된 음성학적 보편 기준이 아니다.
- 단어 내부 중단은 길이만으로 일반 pause로 만들지 않고 `word-break`로 분류한다.
- 첫 발화 전·마지막 발화 후의 양의 길이 구간은 0.20초보다 짧아도 각각
  `leading`·`trailing`으로 기록한다. 내부 pause와 합쳐 유창성 수치로 보고하지 않는다.
- 실제 음성 파일럿에서 경계 재현성을 확인한 뒤 이 기준을 유지하거나 수정한다.
  모델 출력이나 모델 간 승패를 보고 기준을 고르지 않는다.

하한 없이 모든 미세 간격을 기록하는 방식은 작성 범위가 불명확하다.
반대로 “짧음/김”만 적으면 실제 지속 시간이 사라진다. 이 규범안은 수치와 경계
불확실성을 함께 보존하며, 0.20초 선택의 타당성이 검증됐다고 주장하지 않는다.
0.20초 미만의 간격은 이 내부 pause 주석의 필수 범위 밖이다. 따라서 주석이 없다는
사실을 “물리적인 멈춤이 전혀 없었다”로 해석하지 않는다.

이 후보값을 검토한 배경은 L2 독백에서 200ms 기준을 비교한 연구가 있다는 점이다.
해당 연구의 공개 초록은 독백에서 200ms, 대화의 지각 유창성 예측에서는 350ms라는
서로 다른 결과를 보고한다. 이 결과를 OPIc Gold의 정답 기준으로 전용할 수는 없다.
여기서는 파일럿의 출발점으로만 삼는다.
[Gao·Sun·Li의 원 연구 초록](https://journals.sagepub.com/doi/10.1177/02655322251315792).

### 7.2 경계와 불확실성

시간 원점은 **모든 모델에 전달하는 평가 파일의 시작**이다. 시작은 앞 발화의 마지막
확인 가능한 소리가 끝난 지점, 끝은 다음 발화의 첫 소리가 시작한 지점이다.
단어 끝의 작은 자음 소리를 놓치거나 무성음을 무음으로 판단하지 않도록 듣기와
파형을 함께 확인한다. 파형의 낮은 높이나 VAD(음성 구간 탐지) 결과만으로 자동 확정하지 않는다.

`durationSeconds = endSeconds - startSeconds`이고 구간은
`0 <= startSeconds < endSeconds <= 파일 길이`를 만족해야 한다.
소수 둘째 자리까지의 표시는 기록 형식이며 10ms 정확도를 보증하지 않는다.
시작·끝을 확신할 수 없으면 가능한 경계 범위도 기록한다.
예를 들어 시작이 1.20~1.24초, 끝이 1.42~1.45초라면 길이는 0.18~0.25초다.
0.20초 경계를 가로지르므로 `boundary-uncertain`으로 남기고 pause 개수 확정을 보류한다.

시간이 미확정이어도 단어가 확실한 샘플은 단어 평가에 사용할 수 있다.
정확한 단어 Gold와 확정된 시간 Gold의 상태를 따로 기록한다.
순수 무발화 파일은 앞뒤 pause 두 개로 중복 기록하지 않고 전체 구간 한 개를 기록한다.

## 8. 비공개 Gold 기록 예시

아래 문장은 규칙 설명을 위해 만든 가상 발화다. 실제 녹음이나 측정 결과가 아니다.

```text
Um I I w- w- went to— [0.90초 멈춤] I goed home.
```

```json
{
  "conventionVersion": "gold-v1-rc1",
  "sampleId": "restart-001",
  "reviewStatus": "draft",
  "lexicalStatus": "pending-review",
  "timingStatus": "pending-review",
  "evaluationUse": "challenge-only",
  "verbatimTranscript": "Um I I [fragment:f1] went to— [pause:p1] I goed home.",
  "lexicalProjection": "Um I I went to— I goed home.",
  "events": [
    {
      "id": "f1",
      "kind": "fragment",
      "heard": "w- w-",
      "startSeconds": 1.20,
      "endSeconds": 1.55,
      "note": "두 번의 부분 반복. 뒤의 went는 별도의 완전한 단어."
    },
    {
      "id": "p1",
      "kind": "pause",
      "position": "internal",
      "startSeconds": 2.10,
      "endSeconds": 3.00,
      "durationSeconds": 0.90,
      "boundaryStatus": "pending-review"
    }
  ]
}
```

`lexicalProjection`은 검토용 추출 결과다. 이 예시는 조각이 있어 `challenge-only`이므로
현재 주 비교 manifest에 복사하지 않는다. 조각을 삭제한 추출문만 보고 “완전한
verbatim 정답”이라고 부르지 않는다. `goed`는 말한 형태라서 추출 후에도 그대로 남는다.

사건 ID는 샘플 안에서 유일해야 하며 본문의 표식과 같은 사건을 가리켜야 한다.
조각·불명확한 발화는 본문에서 위치를 표시한다. 단어와 겹치는 웃음·늘임 등은
시간 구간과 대상 단어의 몇 번째 출현인지를 사건에 적어 연결한다.
시간을 아직 결정하지 못했으면 값을 추측하지 말고 해당 값을 생략하고 미확정 사유를 남긴다.
본문에 없는 사건과 연결이 끊긴 표식은 최종 검수에서 해결한다.

최종 기록에는 예시의 필드 외에 다음 정보를 함께 보관한다.

- 음성 파일 경로·SHA-256 식별값(파일 내용이 바뀌었는지 확인할 지문), 실제 길이, 목표 화자 가명 ID.
- 작성자·검수자 가명 ID, 각 독립 초안, 불일치와 판정 근거, 날짜.
- 규칙 버전, 표기 사전 버전, 데이터셋 버전, 단어·사건·시간별 검수 상태.
- 보조 자료 사용, 원본에서 자른 경우 원본 식별값과 절단 구간·시간 원점 변환.
- 음성 및 전사 자료의 출처, 허용 목적, 접근 범위, 보존 기한, 삭제 담당·방법.

이 정보는 manifest가 아닌 같은 비공개 자료 묶음에 둔다. Git 제외는 암호화나 접근
통제가 아니므로 민감 자료의 공개 링크·일반 로그 기록을 피한다. 동의 범위가
확인된 평가 음성만 사용하고 운영 사용자 음성을 테스트 자료로 재사용하지 않는다.
외부 STT로 평가할 때는 외부 전송도 허용되는 평가 자료인지 확인한다.

## 9. 작성·검수·확정 절차

1. **자료 준비:** 출처와 보관 조건을 기록하고 실제 평가 파일을 고정한다.
   자르기·변환을 했다면 새 파일 ID와 이력을 부여한다. 모든 후보에 같은 파일을 쓴다.
2. **규칙 연습:** 작성자들이 예제와 소량의 동의 음성으로 규칙을 연습한다.
   사람마다 달리 판단하는 항목은 본 평가 전 표기 사전·규칙으로 해결한다.
3. **독립 작성:** 두 사람이 서로의 초안과 모델 출력을 보지 않고 단어와 사건을 작성한다.
   한 사람만 가능한 경우 `single-reviewed` 임시 자료로 관리하고 독립 검수 Gold라고 부르지 않는다.
4. **불일치 확인:** 단어·필러 형식과 횟수·조각·언어·시간 경계를 분리해 비교한다.
   합의 전 초안과 불일치 수를 보존한다. 합의 후 같은 문장이 됐다는 사실만으로
   작성자 간 일치도가 높았다고 주장하지 않는다.
5. **재청취와 판정:** 불일치한 구간을 정상 속도와 필요한 보조 청취로 검토한다.
   해결되지 않으면 제3 검수자에게 판정을 맡기거나 보류한다. 다수결로 소리 증거를 대체하지 않는다.
6. **추출과 적격성 검수:** 채점용 단어열을 대조하고 아래 평가 묶음을 결정한다.
   단어가 확정되어도 미지원 사건이 있으면 전체 verbatim 자동 채점이 가능한 것은 아니다.
7. **고정:** 확정 자료의 파일 식별값·규칙·사전·데이터셋 버전을 함께 기록한다.
   그 뒤 후보 모델을 실행한다. Gold나 모범 답안을 STT prompt에 넣지 않는다.

| 평가 묶음 | 넣을 자료 | 현 코드에서의 처리 |
|---|---|---|
| 주 단어 평가 (`core-lexical`) | 단어열 합의, 영어 단일 화자, 조각·불명확 구간·단어 내부 중단 없음 | `transcribe`로 manifest에 포함. 필러·완전 반복·문법 오류·false start는 유지 |
| 수동 도전 자료 (`challenge-only`) | 조각, 단어 내부 중단, 혼용 언어, 복수 화자 등 현 채점 미지원 | Gold와 음성을 보관하고 수동 검토. 주 WER와 합산하지 않음 |
| 판정 보류 (`hold`) | 정답 단어·필러·조각 등에 해결되지 않은 후보가 있음 | 주 비교 manifest에서 제외하고 이유·수를 보고 |
| 비음성 검사 | 확인된 무음·기침·잡음 등, 언어적 발화 없음 | 빈 정답과 `empty-or-rejected` |
| 잘못된 입력 검사 | 손상·지원 불가 입력 등 전사 이전 거부 대상 | `rejected`; 음성 내용의 정답 품질과 별도 평가 |

필러만 있는 `um uh`도 전사할 발화이며 `transcribe` 대상이다.
조각만 있거나 알아들을 수 없는 발화만 있는 음성을 비음성 검사로 옮기지 않는다.
이 묶음 이름은 수동 관리 규칙이며 **현재 CLI의 자동 필터가 아니다**.
주 비교 manifest에는 사람이 적격 샘플만 넣어야 한다. tag만 붙여도 자동 제외되지 않는다.

### 확정 전 점검표

- [ ] 원음 없이 문맥만으로 추가한 단어가 없다.
- [ ] 필러·완전 반복·버린 말·문법 오류가 모두 남아 있다.
- [ ] 조각·늘임·중단을 서로 혼동하지 않았고, 횟수와 순서를 재확인했다.
- [ ] 불확실한 구간을 무음이나 빈 정답으로 바꾸지 않았다.
- [ ] 숫자·축약형·약어·고유명사가 공통 표기 기준을 따른다.
- [ ] 두 독립 초안과 판정 근거가 남아 있고 단어와 시간의 확정 상태를 구별했다.
- [ ] 본문 사건과 주석이 연결되고, 시간 원점·구간·길이가 일치한다.
- [ ] 현재 채점 범위를 벗어난 자료가 주 비교 manifest에 섞이지 않았다.
- [ ] 원음·Gold·추출문·규칙·사전·데이터셋 식별값과 보관 조건을 함께 기록했다.

## 10. 현재 채점기가 보장하는 것과 보장하지 않는 것

코드 근거는 [`transcription_metrics.py`](../../backend/app/evals/transcription_metrics.py),
[`transcription_dataset.py`](../../backend/app/evals/transcription_dataset.py),
[`transcription_report.py`](../../backend/app/evals/transcription_report.py)다.

- NFKC 문자 정규화, 소문자화, 곡선 apostrophe 치환 후
  `[a-z0-9]+(?:'[a-z0-9]+)*` 패턴으로 단어를 추출한다.
  문장부호 대부분은 경계로 작용하지만 apostrophe는 단어 안에 남는다.
- `[pause:1.2]`는 설명으로 이해되지 않고 `pause`, `1`, `2`로 추출된다.
  `w-went`는 `w`, `went`이며, 한글은 단어로 보존되지 않는다.
- WER는 이 단어열의 대체·삭제·삽입을 비교한다. 숫자·축약형·약어의 의미 동등성,
  불명확 구간 제외, 복수 정답, 단어 조각의 선택적 채점을 지원하지 않는다.
- 필러와 인접 반복 지표는 **종류별 개수**를 비교한다. 같은 개수를 잘못된 위치에
  출력해도 보존으로 셀 수 있고 문법적 반복과 망설임을 구분하지 못한다.
- 사건 파일, 검수 상태, 음성 해시, 제외 묶음, pause 시간은 자동 검증하지 않는다.
  같은 dataset version 문자열만 같다고 실제 파일과 Gold 내용의 동일성이 보장되지는 않는다.

따라서 현재 자동 점수는 **선정된 샘플의 단어 전사 품질**이다. 말더듬·pause까지 포함한
전체 verbatim 충실도의 완성된 점수라고 보고하지 않는다. 모델이 사건 태그를 출력한
경우에도 현 WER는 그 태그를 오채점할 수 있으므로 원시 결과와 그 한계를 함께 기록한다.
특정 모델 출력에서만 태그·필러·조각을 지워 비교를 유리하게 만들지 않는다.

## 11. 규칙 파일럿과 버전 관리

현재는 실제 OPIc 음성의 독립 작성 결과로 이 규칙의 재현성을 검증하지 않았다.
`gold-v1-rc1`은 검토 가능한 기준안이며 `gold-v1` 확정판으로 표시하지 않는다.
각 핵심 현상을 포함하는 소량의 동의 음성으로 먼저 작성 실험을 한다.

파일럿에서는 단어 불일치, `um/uh` 등 형식 불일치, 반복 횟수, 조각 판정,
불명확 구간, pause 경계 차이, 소요 시간, 보류 비율을 기록한다.
현재 WER만으로 작성자 일치도를 대신하면 조각·시간 불일치를 놓친다.
개인 청력 문제인지 규칙의 빈틈인지 구별하고 반복되는 규칙 충돌은 예제로 보강한다.

확정 조건은 핵심 범주에 대한 독립 작성과 판정 기록이 있고, 반복적으로 발생한
규칙 해석 충돌이 해결되었으며, 남은 불확실성을 어떤 묶음으로 관리할지 명확한 것이다.
아직 자료가 없으므로 임의의 일치율 목표나 “검증 완료” 표시를 만들지 않는다.
사용자 검토와 파일럿 근거를 거쳐 확정판을 발행한다.

- 확정 전 규칙 변경은 `gold-v1-rc2`처럼 후보 번호와 변경 이유를 남긴다.
- 확정 후 단어 경계·필러·pause 기준 등 의미가 달라지면 `gold-v2`처럼 규칙 버전을 올린다.
- 같은 규칙 아래 특정 Gold를 정정하거나 파일·샘플 구성을 바꾸면 `stt-eval-vN`을
  새로 부여한다. 사전 변경이 단어열에 영향을 주어도 해당 Gold와 데이터셋을 갱신한다.
- 옛 Gold·새 Gold를 덮어쓰지 않고 변경 이유와 적용 범위를 기록한다. 평가 중 오류를
  발견하면 해당 비교를 잠정 중단하고, 모든 모델을 같은 새 Gold로 다시 채점한다.
  입력 음성까지 바뀌었다면 해당 음성에 대한 모델 실행도 다시 해야 한다.
- 모델 성능이 좋아 보이는 쪽으로 정답을 선택하지 않는다. 사후 정정은 원음과
  규칙으로 설명할 수 있어야 하며, 가능하면 모델명을 가린 상태에서 재검수한다.

## 12. 외부 지침에서 참고한 원칙과 프로젝트의 선택

다음은 원문을 확인한 1차 자료다. 외부 지침의 특정 기호·채점 방식을 그대로
호환 구현했다는 뜻은 아니다. 위 규칙의 상태와 현 코드 지원 여부는 이 문서가 명시한다.

- [LDC Communicator Transcription Guidelines, v1.2](https://catalog.ldc.upenn.edu/docs/LDC2002S56/comm_transcription_spec_v1.2.html):
  숫자를 말한 단어로 기록하고, 필러·미완성 단어·비표준 문법을 다룬다.
  다만 구어 축약을 풀어 적거나 조각을 선택적으로 채점하는 해당 지침의 방식을
  이 프로젝트가 그대로 채택한 것은 아니다.
- [TalkBank CHAT Manual](https://talkbank.org/0info/manuals/CHAT.html):
  반복·자기 수정·조각·늘임·불명확 발화·시간을 서로 구별하는 체계를 참고했다.
  CHAT 전체 형식과 분석 도구는 도입하지 않았다.
- [LDC ATIS SRO Transcription Conventions](https://catalog.ldc.upenn.edu/docs/LDC94S19/sro_spec.html):
  상세 전사와 채점용 표현을 나누는 선례를 참고했다. 이 프로젝트의 추출기와
  주석 자동 검증은 아직 구현되지 않았다.
- [Matzinger 등의 pause 연구, Box 1](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0230710):
  자음의 닫힘·약한 말소리와 pause를 구별하고 청취로 확인해야 한다는 방법론을 참고했다.
  해당 연구가 사용한 0.1초 하한을 본 프로젝트의 기준으로 채택한 것은 아니다.
- [Gao·Sun·Li의 L2 pause 기준 연구](https://journals.sagepub.com/doi/10.1177/02655322251315792):
  공개 초록의 과제별 결과를 잠정 하한 검토에 참고했다. 유료 본문 전체나 원자료를
  재분석한 것은 아니며, 본 프로젝트에서의 효과는 검증되지 않았다.

`0.20초` pause 후보 기준, 후보판·검수 상태, 현 코드에 맞춘 평가 묶음은
OpenCoachAI의 설계 선택이다. 위 자료의 보편 표준이나 검증된 OPIc 기준으로 인용하지 않는다.
대안과 비용은 [ADR 0001](../decisions/0001-gold-transcript-and-timing.md)에 기록한다.
